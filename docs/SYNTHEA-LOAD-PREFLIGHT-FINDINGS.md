# Synthea Load: Code Mapping Findings

Date: 2026-10-05
Test system: dev/SQA VistA with the WorldVistA VistA-FHIR-Data-Loader ("SYN" package)
Test patient: Lan153 Torphy630 (fictional, generated by Synthea), loaded as DFN 100969

## Summary

A full Synthea patient loaded successfully, but many records were rejected because the loader has
no mapping for their codes. Most rejected records are:

- **Procedures**: 247 of 259 (95%) rejected. SNOMED CT and dental CDT codes have no entry in the
  loader's mapping table.
- **Vitals**: 97 of 315 (31%) rejected. The loader accepts only a short hardcoded list of vitals.
- **Labs**: 81 of 378 (21%) rejected. Some LOINC codes have no map entry; others map to a lab test
  name that does not exist in the VistA LABORATORY TEST file (#60).

A read-only "preflight" check now predicts these failures before a patient is loaded. For this
patient its predictions matched the actual load results almost exactly (table below).

## Procedures: code sets and examples

The bundle's 259 procedure resources use 89 distinct codes from two code sets:

| Code set | Distinct codes | Resources | Example |
|---|---|---|---|
| SNOMED CT (`http://snomed.info/sct`) | 75 | 239 | 430193006 Medication reconciliation (procedure) |
| CDT, American Dental Association (`http://www.ada.org/cdt`) | 14 | 20 | D1110 Prophylaxis, adult |

By SNOMED semantic tag, 223 resources are "procedure", 14 are "regime/therapy" and 2 are
"observable entity". The 20 CDT resources are dental codes and carry no SNOMED tag.

The loader looks each SNOMED code up in a mapping table named `sct2os5`. The lookup code is routine
`SYNDHPMP`, but the table itself is data stored in a VistA global: `^SYN(2002.030,"sct2os5","direct",<code>,<target>)`.
That data is installed by the loader's own KIDS build (its post-install merges the `^SYN` global
in); it is not a standard VistA national file. If the code has no entry, the procedure is rejected
with `-1^Code <code> not mapped`. There is no CDT map in this global, so every dental procedure is
rejected. Adding mappings is a data change (new nodes under that global), not a code change.

## Vitals

The loader converts the incoming LOINC code to SNOMED with a hardcoded table in routine `SYNFVIT`.
Six vitals are supported: weight, height, blood pressure, heart rate, respiratory rate and pain.

| Count | LOINC | Description | Result |
|---|---|---|---|
| 26 | 39156-5 | Body mass index (BMI) | not in table |
| 22 | 59576-9 | BMI percentile for age and sex | not in table |
| 13 | 77606-2 | Weight-for-length percentile | not in table |
| 13 | 9843-4 | Head circumference | not in table |
| 13 | 8289-1 | Head circumference percentile | not in table |
| 7 | 2708-6 | Oxygen saturation, arterial blood | not in table |
| 3 | 8310-5 | Body temperature | not in table |

Which of these can be fixed depends on whether VistA has a matching vital type. The GMRV VITAL TYPE
file (#120.51) on the test system contains: blood pressure (1), temperature (2), respiration (3),
pulse (5), height (8), weight (9), abdominal girth (10), audiometry (11), fundal height (12), fetal
heart tones (13), head circumference (14), hearing (15), tonometry (16), vision corrected (17),
vision uncorrected (18), central venous pressure (19), circumference/girth (20), pulse oximetry
(21) and pain (22). The loader's SNOMED-to-vital-type map (`sct2vit`) uses these numbers.

| Rejected vital | Resources | Vital type exists? | Fix |
|---|---|---|---|
| Oxygen saturation 2708-6 | 7 | Yes (21) | Add the LOINC code to the `SYNFVIT` table; the table has pulse oximetry keyed by SNOMED instead of LOINC |
| Body temperature 8310-5 | 3 | Yes (2) | Add the LOINC code to the `SYNFVIT` table (it only has 8331-1) |
| Head circumference 9843-4 | 13 | Yes (14) | Add LOINC and SNOMED entries |
| BMI 39156-5 | 26 | No (VistA calculates BMI from height and weight) | Not needed; skip |
| BMI percentile 59576-9 | 22 | No | Cannot load as a vital |
| Weight-for-length percentile 77606-2 | 13 | No | Cannot load as a vital |
| Head circumference percentile 8289-1 | 13 | No (percentile, not a measurement) | Cannot load as a vital |

So about 23 of the 97 rejected vitals could be recovered with small code and data changes in the
loader. 26 more (BMI) are not a loss because VistA calculates BMI from the height and weight that
do load. The remaining 48 (the three percentile measures) have no VistA vital type to load into.

## Labs

For labs the loader looks up the LOINC code in a LOINC-to-lab-name map, then requires the resulting
name to exist in the LABORATORY TEST file (#60). Two failure types result.

**LOINC code not mapped (38 resources)**: for example 33762-6 NT-proBNP, 33914-3 glomerular
filtration rate, 19123-9 magnesium, 2276-4 ferritin, 10230-1 left ventricular ejection fraction,
5794-3 urine hemoglobin, 630-4 urine bacteria culture, 88020-3 and 88021-1 NYHA functional class.

**Mapped, but the target lab test is not in file #60 (43 resources)**: these records reach
"ready to load" and are then rejected with `Couldn't find ien for LAB_TEST (#60)`.

| Count | LOINC | Mapped to lab name |
|---|---|---|
| 13 | 788-0 | RDW-CV |
| 8 | 2885-2 | TOT PROT |
| 8 | 1975-2 | TOT. BIL |
| 8 | 6768-6 | ALK PHOS |
| 5 | 32207-3 | PDW |
| 1 | 5804-0 | TOT PROT |

These are the cheapest fixes. Comparing the names with `^LAB(60,"B")` (1,581 lab tests on the test
system) shows that most of the tests already exist under a different spelling, so the fix is to
change the mapped name, not to add a test:

| Mapped name | Existing file #60 test (IEN) |
|---|---|
| TOT. BIL | TOT. BILIRUBIN (186) |
| TOT PROT | TOTAL PROTEIN (184) |
| ALK PHOS | ALKALINE PHOSPHATASE (188) |
| RDW-CV | RDW (416) |
| PDW | none found |

Also, some unmapped LOINC codes have a matching test in #60: GFR 33914-3 could map to
eGFR (CKD-EPI) (5145), and magnesium (201) and ferritin (113) exist. The loader's lab map in
`SYNQLDM` already lists magnesium and ferritin, so their "unmapped" result may come from a stale
cached copy of the map (`^XTMP("SYNQLD","MAPS")` is only rebuilt when it is missing). This is a
hypothesis; rebuilding the cache and re-running the preflight check will confirm it. No equivalent
exists for NT-proBNP, left ventricular ejection fraction or the NYHA scores.

## Preflight check: predicted vs. actual

| Domain | Predicted to fail | Actual |
|---|---|---|
| Procedures | 247 of 259 | 247 |
| Vitals | 97 of 315 | 97 |
| Labs, unmapped | 38 | 38 (30 cannot load, 8 skipped) |
| Labs, mapped but not in file #60 | 43 | 42 |

How it works:

1. `preflight-synthea.js` reads a Synthea FHIR bundle offline and lists every distinct SNOMED, LOINC,
   RxNorm, CVX and CDT code with counts.
2. `preflight-vista.js` sends the procedure, vital and lab codes to a VistA RPC
   (`CDSP UTIL LOAD PREFLIGHT`). The RPC calls the same lookup functions the loader uses and
   writes nothing.
3. The result is a per-code report of what will be rejected and why.

Not yet checked: medications (RxNorm), conditions (SNOMED to ICD) and encounters.

## Conditions

Conditions are mapped from SNOMED to ICD (`sct2icdnine` for visits before 2015-10-01, `sct2icd`
after). A condition with no ICD map still loads through a SNOMED-only fallback path. A condition with an
ICD map goes through the PCE path (`PRBUPDT^SYNDHP62`).

For this patient, 54 of 63 conditions had no ICD map and all 54 loaded through the fallback. The other
9 had an ICD-9 map and all 9 failed, with only `-1^<visit IEN>` and no message:

| SNOMED | ICD-9 | Visit date |
|---|---|---|
| 90460009 | 959.09 | 1953-09-07 |
| 44465007 | 845.00 | 1957-10-25 |
| 43878008 | 034.0 | 1962-06-28 |
| 53963006 | 521.1 | 1967-12-12 |
| 105531004 | V60.1 | 1968-12-10 |
| 10509002 (x2) | 466.0 | 1969-08-02, 1971-07-10 |
| 398254007 | 642.40 | 1975-06-10 |
| 162864005 | V85.30 | 1975-12-23 |

All failing visits are before 1978. A likely cause is that ICD-9 codes are not effective on those dates
in VistA, so PCE rejects them. A lookup on the test system supports this: for 959.09 on the 1953-09-07
visit date, `$$ICDDX^ICDCODE` returned an effective date of 1978-10-01 (FileMan 2781001) and the flag
"CODE TEXT MAY BE INACCURATE". Every failing visit (1953 to 1975-12-23) is earlier than that date. It
is not proven that PCE rejects the code for this reason: the patient has no ICD-mapped condition after
1978 to compare. A patient with recent visits would show whether the ICD path works at all.

## Other observation: encounter location

Every loaded encounter becomes a visit at the GENERAL MEDICINE hospital location, regardless of the
Synthea encounter class (this patient's bundle has 94 ambulatory, 7 emergency, 2 inpatient and 1
home-health encounters). The loader sets the location with one fixed outpatient mapping
(`$$MAP^SYNQLDM("OP","location")`) and the provider the same way, so all data is attributed to a
single clinic and a single provider.

## Caveats

- Findings come from one patient; other Synthea patients will use other codes. Run the preflight
  check on a bundle before loading it.
- Mapping behavior is taken from the loader source (SYNDHP65, SYNFVIT, SYNFLAB) and confirmed
  against this one load.
- The patient is fictional and the data is synthetic.
